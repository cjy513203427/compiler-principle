# 编译手记

基于宫文学《编译原理实战课》的中文交互笔记。参考同级 `transformer-animation` 的学习方式：**先预测，改输入，单步核对，再用自己的话复述**。本项目独立实现，不依赖兄弟项目运行。

## 本地运行

需要 Node.js 22.12+（或更新的受支持版本）和 npm；部署构建使用 `.nvmrc` 中的版本。

```sh
npm ci
npm run dev
```

打开终端显示的地址（默认 `http://127.0.0.1:5173`）。所有编译与执行发生在浏览器中，无后端、账号或 API Key。

线上版本公开发布在 Cloudflare Workers：<https://compiler-principle.cjyhobbyprojects.workers.dev>（英文 `/en/`、德文 `/de/`）。只上传静态构建产物，不加载统计脚本，详见 [部署说明](docs/cloudflare.md)。

```sh
npm run check       # 类型检查、算法与状态测试、生产构建
npm run test:e2e    # 桌面与手机尺寸的浏览器测试，需要本机 Chrome
npm run preview    # 本地预览生产构建
npm run deploy -- --dry-run  # 检查、构建并校验 Cloudflare 部署配置，不上传
npm run deploy     # 发布到 Cloudflare（需先 npx wrangler login）
```

浏览器测试使用 Chrome channel；未安装 Chrome 时，可安装 Chrome，或在 `playwright.config.ts` 移除 `channel` 并安装 Playwright Chromium。

界面提供中文、英文、德文三种语言：中文在 `/?lab=…`，英文在 `/en/?lab=…`，德文在 `/de/?lab=…`，左侧目录底部可切换并保留当前实验与步骤。新增或修改界面文字的流程见 [docs/i18n.md](docs/i18n.md)。

## 教学语言

```c
int result = 2 + 3 * 4;
print(result);

int x = 10;
{
  int x = 20; // 内层声明遮蔽外层
  print(x);
}
print(x);
```

支持 `int`、`bool`，变量声明和赋值，`+ - * /`、一元负号、括号、语句块、`print`、`//` 单行注释。语句需要半角分号。只有 ASCII 标识符；`int`、`bool`、`print`、`true`、`false` 是保留字。

整数使用 JavaScript 安全整数，除法按精确整数向零取整（2026-11-26 起不再先做浮点除法，大被除数不再被舍入；结果没有 −0），溢出和除零报告运行时错误。无隐式类型转换。初始化表达式先分析，新绑定随后引入；同层不能重复声明，内层允许遮蔽。源码限制 2000 字符，括号/一元运算/语句块嵌套限制 64 层。

支持 `if / else` 和 `while`，条件必须是 `bool`，主体必须用花括号。比较运算支持 `< <= > >= == !=`，算术优先于比较、比较优先于相等性。大小比较仅用于整数，相等性比较要求两侧类型相同。暂不支持 `break / continue`、逻辑短路、函数、字符串、浮点、闭包、对象与垃圾回收。IR 与字节码均为自定义教学格式，**不是 LLVM IR、JVM 或 CPython 的真实指令**。实验 17、18 有教学用的寄存器分配、指令排序与寄存器机，但没有指令选择或机器码生成。

```c
int i = 1;
int sum = 0;
while (i < 4) {
  sum = sum + i;
  i = i + 1;
}
if (sum == 6) {
  print(sum);
} else {
  print(0);
}
```

第七个实验 `/?lab=cfg` 从原始 IR 划分基本块，再由虚拟机的真实执行快照生成按块回放的路径。图保留全部可能边，高亮本次实际经过的边；点击块可检查完整指令，前进/回退时变量与输出随快照更新。跳转使用生成的标签地址，不是写死的动画路线。

每次回放最多执行 2000 条字节码，避免错误循环阻塞界面。达到上限时明确显示暂停，**不代表已经证明程序不会终止**，暂停前的输出也不能用于判断完整行为等价。

## 算法与数据流

```text
source → tokenize → parse → analyze → generateIR → optimize → generateBytecode → execute
           tokens     AST     绑定/类型     TAC          TAC          栈式指令        快照
```

计算逻辑与 UI 分离，不使用 `eval` 或 `Function` 执行输入。每步状态来自真实扫描、构树、分析或执行。AST 回放展示最终树并高亮当时构建的节点，不伪装成增量生成的树。

直线代码沿用顺序传播与反向清理；**分支/循环已接入跨块优化**：先求解条件常量事实，再传播、折叠，最后依据可执行边删除不可达块，并在改写后的 CFG 上迭代活跃性，清理无用复制和标签。可能报错的未折叠算术仍然保留，输出与异常顺序不重排。三个开关分别控制表达式折叠、常量替换、分支/不可达与无用写入清理；分析本身不依赖开关，也不借用一次执行的结果。

第八个实验 `/?lab=dataflow` 展示原始 CFG 的分析：每次处理一个块，合并可执行前驱的 OUT，求出本块 IN / OUT，直到事实和边都不再变化。⊥ 是尚无信息，常量 c 是确定值，⊤ 表示不能确定唯一常量。循环可能让早期常量变成 ⊤；两条路径都赋 7 时仍可合并为 7。最后一步可选择任意块查看完整事实，也可查看原始结构图上的保守活跃变量集合。分析与执行快照清楚区分。

条件常量传播与活跃性均最多 200 轮；常量分析未收敛时保留原始 IR，不把未分析路径当成不可达。分析中间回放最多保留 240 次块处理，最终表始终展示完整分析结果，达到记录上限不会提前停止求解。实现为可变变量上的**稠密条件常量传播**，没有 SSA、φ、取值范围分析、循环展开或 LLVM 的稀疏实现。

页面实际运行原始版和优化版，比较当前程序的输出与错误；任一版本达到 VM 回放上限时，比较结果为无法判定。这个对照不等于一般性的语义等价证明，IR 指令数也不等于运行时间。

第九个实验 `/?lab=dominance` 从原始 CFG 的全部结构边求解支配集合，逐轮展示前驱交集与候选移除。完成后可查询 A 是否支配 B；若不支配，显示一条避开 A 的结构路径。直接支配树、自然循环的 header / latch / preheader / exit block、循环嵌套与支配边界都来自分析结果，不借用 VM 执行路径，也不按节点的绘图位置判断回边。

φ 面板按变量定义块计算**迭代支配边界的候选位置**，没有活跃性裁剪，所以可能多余；本页不生成版本名，不改写 IR 或执行候选 φ。继续到实验 13「静态单赋值」观察真正的 φ 插入与重命名。自然循环识别不等于枚举所有有向环或不可约区域。支配分析最多 200 轮，未收敛不发布后续结论；仅截断前 240 次块处理的回放，最终集合仍完整。结构可达与绕行路径不代表路径上的条件可同时成立。

## 正则与自动机

第十个实验 `/?lab=automata` 对应原书第 02 讲“用两种方式构造有限自动机”的第二种方式：只写词法规则，自动生成扫描器。输入格式借用 flex 的 `%%` 分隔：

```text
Int: int
Id: [a-zA-Z][a-zA-Z0-9]*
Num: [0-9]+
skip: [ \t\n]+
%%
int intA 42
```

`%%` 上方每行一条“名称: 正则”，越靠前优先级越高；名为 `skip` 的规则匹配后丢弃；`%%` 下方都是待扫描的输入。这个实验使用自己的输入，不经过 Mini C 编译；切换到其他实验时，原来的 Mini C 程序会保留。

回放分三段，每一步都来自 `src/compiler/automata.ts` 的真实计算：

1. **正则 → NFA**：按原书图 7–11 的拼接规则逐个子表达式构造。连接时把前一段的结束状态与后一段的开始状态合并；`* + ?` 和 `|` 用 ε 边。清单采用原书 `0 ε -> 2` 的写法。
2. **子集构造**：先求 ε-闭包，把全部边上的字符集切成互不相交的输入类，再逐个 DFA 状态求 move 与闭包。一个 DFA 状态同时含多条规则的接受状态时，取排在前面的规则；完全胜不出的规则和能匹配空串的规则会被标出。
3. **最长匹配扫描**：一直读到 DFA 无路可走，再回到最近的接受位置生成 Token，并显示退回的字符数。空词素不会成为 Token。

最后一步可以查看 DFA 图（键盘可选状态）、DFA 状态表、NFA 清单和“NFA 回溯对照”。回溯对照参照原书 `matchWithNFA` 的过程，按建边顺序深度优先做整串匹配，并列出每次尝试的状态和位置。它与 DFA 选出的规则一致，代价却可能大很多，例如 `(a|aa)*b` 在 12 个 a 上要尝试 4000 多次。

支持字符、`[ ]` 字符集与区间、`[^ ]`、`.`（除换行）、`\d \w \s`、`\n \t \r`、`| * + ?` 和括号；正则中的空格只用于排版。字母表限于 ASCII 可打印字符与 `\t \n \r`。本页不做 DFA 最小化，继续到实验 14 查看分割细化与扫描对照；不支持 `{m,n}`、锚点、捕获组和反向引用。限制为：最多 8 条规则，每条 80 字符，输入 300 字符；NFA 300 个状态，DFA 64 个状态。DFA 超限时停止构造，不发布扫描结果。扫描回放记录前 1500 步，Token 结果始终完整。回溯每个 Token 最多尝试 5000 次，只显示前 240 次。

## 文法与预测分析

第十一个实验 `/?lab=grammar` 对应原书第 03 讲“两个基本功和两种算法思路”。实验 02 演示了手写的递归下降，这里接着回答：一个规则有几种写法时，解析器怎样只看下一个 Token 就选对。输入同样用 `%%` 分隔：

```text
exp -> mul add'
add' -> + mul add' | ε
mul -> pri mul'
mul' -> * pri mul' | ε
pri -> Num | ( exp )
%%
2 + 3 * 4
```

`%%` 上方每行一条产生式，候选用 `|` 分开，空串写 `ε`，以 `|` 开头的行接着上一行；第一条的左边是开始符号。出现在左边的名字是非终结符，其余都是终结符。输入可省略空格：与终结符同名的单词和符号直接对应，文法里有 `Num` / `Id` 时，数字和其余单词分别记作它们。

回放分四段，全部来自 `src/compiler/grammar.ts` 的真实计算：

1. **FIRST**：一轮轮扫描全部产生式，把能借到的 Token 加进去，直到某一轮没有变化（不动点）；每一步说明这个 Token 是从哪里借来的。
2. **FOLLOW**：开始符号先放 `$`，再按“后面是什么”和“在末尾就继承左边”两条规则迭代。
3. **分析表**：逐条产生式填表，因 FOLLOW 填入的格子标 F；格子里有两条时报告 FIRST/FIRST 或 FIRST/FOLLOW 冲突，并且不做解析。
4. **用表解析**：显示栈、输入光标、本次查到的格子，解析树随步骤长出来；出错时说明此处能接受哪些 Token。

能识别直接与间接左递归，用“解析 add() → 解析 add() → …”演示递归下降为何停不下来；直接左递归可一键改写成 `A -> β A'`、`A' -> α A' | ε` 后重新分析。移进 / 规约见实验 12；本实验不提取左公因子、不做错误恢复。限制为：16 个非终结符、40 个候选、每个候选 10 个符号、输入 60 个 Token、解析回放 600 步。

单元测试用龙书经典表达式文法的 FIRST / FOLLOW 作为参照，另用“列举文法能生成的全部短串”作为独立对照，检查表驱动解析的接受与拒绝，并确认左递归改写前后接受同一组短串。

## 移进与规约

第十二个实验 `/?lab=lr` 对应第 03 讲后半的 LR 算法：不从树根往下猜，而是把 Token 移进工作区，凑齐一条产生式的右边再规约成左边的名字。文法写法与实验 11 相同，FIRST / FOLLOW 也复用实验 11 的计算。

1. **项目集**：自动加上 `S′ → 开始符号`，从“带点的产生式”出发求闭包，按点后面的符号前进，得到全部 LR(0) 状态；每个项目注明来自哪个状态或因哪个名字被闭包加入。
2. **ACTION / GOTO**：点后面是 Token 就移进；点在末尾且下一个 Token 属于 FOLLOW(左边) 就规约（SLR(1)）；同一格有两个动作时报告移进/规约或规约/规约冲突，不做解析。
3. **移进 / 规约**：工作区按栈顺序显示状态号和已经拼好的小树，规约时几块合成一块；移进时若已有完整项目却不规约，会说明下一个 Token 不在 FOLLOW 里。接受后列出最右推导，即规约顺序倒过来读。

原书示例的左递归文法 `add -> add + mul | mul` 不用改写即可解析，乘法优先、加法左结合；实验 11 中“开头相同”的 LL(1) 冲突文法在这里也没有冲突。原书示例称 LR(1)，本实验采用更简单的 SLR(1)：例如 `S -> L = R | R`、`L -> * R | Id`、`R -> L` 在 SLR(1) 下有冲突，页面会如实报告。不实现完整 LR(1) / LALR、错误恢复和按优先级消解冲突。最多 80 个状态，解析回放 600 步。

单元测试核对经典表达式文法的 12 个 LR(0) 状态，对解析树求值验证优先级与结合性，检查最右推导每一步都展开最右边的非终结符，并用“列举文法能生成的短串”作为独立对照。

## DFA 最小化

## 寄存器分配（Register allocation）

第十七个实验 `/?lab=regalloc` 回答原书第 08 讲的问题：IR 假设寄存器无限，CPU 只有 K 个，哪些值留在寄存器，哪些溢出到栈。输入仍是 Mini C，分配对象是**未优化的原始三地址代码**，让每个临时值和寄存器压力都可见。编辑器下方可选 K（2–8）与算法，切换后重新分配并从头回放；两项设置写入分享链接（`regs`、`alloc`），越界值回到默认 K = 3、图着色。

1. **逐条活跃性**：从最后一条指令往前，求每条指令之后仍要读取的值。单元测试核对它在每个基本块首尾与实验 08 的块级结果一致。
2. **图着色**：写入某值时与此后仍活跃的值连干涉边，复制 `x = y` 不与 `y` 连边。度数 < K 的点先压栈（Chaitin 简化）；都 ≥ K 时按“使用与定义次数 × 10^循环深度 ÷ 度数”选可能溢出的点，弹出时仍有空色就保住（Briggs 乐观着色）。弹出时偏好复制另一端的寄存器，两端同寄存器的复制最后删去。
3. **线性扫描**：每个值合成一个连续活跃区间，按起点扫描、释放已结束区间；寄存器不够时溢出结束最晚的区间（Poletto & Sarkar）。区间忽略空洞，所以“区间空洞”预设在 K = 2 时只有线性扫描需要溢出。
4. **溢出重写**：溢出的值改放栈槽，每次读取前插入 load、写入后插入 store，用只活一条指令的 `x~n` 承接并标为不可再溢出，然后重新分析，最多 16 轮。K ≥ 2 时一定能结束。
5. **核对与执行**：在最终代码上重新求活跃性，独立检查每次写入都不覆盖仍要读取的值；再把变量换成寄存器名，由教学寄存器机执行，比较输出与错误是否与原始 VM 一致。完成页另列 K = 2–8 × 两种算法的溢出数、静态与执行时内存访问次数。

6 个预设：循环变量优先留下、表达式压力、区间空洞、复制同寄存器、溢出后保留除零、嵌套循环的溢出代价。分配与执行回放各保留前 240 步，最终结果完整；寄存器机最多 2000 条指令，任一执行超限只显示无法判定。寄存器全部等价，没有调用约定、预着色、复制合并、区间拆分、重新物化或栈槽复用；寄存器机是教学格式，不是 x86 / ARM，也不生成机器码。单元测试对全部 Mini C 预设与 40 个固定种子随机程序，在每个 K 和两种算法下检查分配与执行结果。

## 指令排序与窥孔优化（Instruction scheduling & peephole）

第十八个实验 `/?lab=schedule` 接着原书第 08 讲的后端流程：寄存器分配之后再做一次指令排序，因为溢出带来了新的内存访问。输入仍是 Mini C，沿用实验 17 的 K 与算法设置（同样写入分享链接）。

1. **窥孔优化**：宽 2 的窗口滑过分配后的寄存器代码，规则为：存后立即读回同一寄存器的冗余 load（原书例子）、读回到别的寄存器时改为复制、连续两次 store 同一栈槽、跳到下一条的 goto、自身复制。标签会打断窗口。
2. **依赖图**：每个基本块内列出真依赖（RAW，带延迟）、寄存器复用带来的反依赖（WAR）与输出依赖（WAW）、栈槽依赖，以及 print 与可能溢出 / 除零的算术之间的顺序约束；块末跳转固定在最后。
3. **列表调度**：按加权关键路径设优先级，逐周期选出就绪指令，没有就绪指令时记为空转。

## 公共子表达式与循环外提（CSE & LICM）

第十九个实验 `/?lab=cse` 对应原书第 07 讲的中端优化，输入是 Mini C，处理未优化的原始三地址代码。

1. **可用表达式**：前向分析，合并取所有前驱的交集；改写操作数会让用到它的表达式失效。逐块回放 IN / OUT。
2. **公共子表达式消除**：在可用的位置把重复运算改为复制。若某一条计算在所有路径上都仍有效，直接复制它的临时值（原书的 `y := x`）；若各分支分别算过，就新建 `cseN`，在每次计算后保存结果，汇合后从它复制。只在一条分支上算过属于部分冗余，不做。
3. **本地值编号对照**：在每个基本块里找“名字不同、值相同”的计算（原书的 `w + 4` 与 `x + 4`），只作对照，不改代码。
4. **循环不变代码外提**：用实验 09 的自然循环，结果唯一赋值、操作数不在循环内改写（或本身已外提）的计算是不变量，外提到循环头之前。可能溢出或除零的运算只从循环条件的计算中外提；循环体中的只在不会报错时外提，并列出保留在原处的原因。循环零轮时，外提的比较仍会多算一次，结果不变。

原始、消除后、外提后三个版本都交给原栈式 VM 执行，比较输出、错误与实际执行的运算次数。7 个预设：原书 x、y、中间改写失效、两条分支都算过、循环条件里的不变量、循环体里的不变乘法、值编号、保留除零。单元测试对全部 Mini C 预设与 60 个固定种子随机程序检查三版本一致，并在原始执行中逐次核对每处复用时表达式确实仍然有效、值相同。没有部分冗余消除、全局值编号、复制传播、循环倒置或强度削减。

## 垃圾收集（Garbage collection）

## SSA 优化与复制合并（SSA optimization & coalescing）

第二十一个实验 `/?lab=ssaopt` 接着实验 13、15，输入同一份 Mini C 程序，在校验通过的标量 SSA 上运行三项稀疏优化与保守复制合并：

1. **稀疏条件常量传播（SCCP）**：同时维护可执行控制流边与 SSA 格值两个工作表。φ 只合并已激活前驱边，不可达分支不会污染格值；版本格值变化时只沿 def-use 链唤醒直接使用者，并与实验 08 的稠密块扫描次数对照。
2. **SSA 复制传播、平凡 φ 化简与稀疏死代码删除**：沿唯一定义直接替换复制、化简单前驱或同值 φ，再从 `print`、控制流指令与可能除零/溢出的算术出发反向标记，清理无用定义与无用 φ，最后重新通过 `validateSSA` 并由 SSA 解释器执行。
3. **干涉图保护的保守复制合并**：将优化后的 SSA 消除 φ 回到普通 IR，复用逐条活跃性与干涉图检查每条变量间复制 `d ← s`；不干涉时合并为同一变量并消去自身复制，存在干涉（如经典的 Briggs 丢失复制问题与复制传播形成的交换环）时拒绝合并并指出冲突指令。

原始 IR、原始 SSA、优化后 SSA、未合并消除与合并消除全部实际执行并对照输出、错误与变量间复制数量。7 个预设覆盖不可达分支不污染常量、循环 φ 合并、丢失复制反例、复制传播造出真实交换环、清理无用 φ 链、双分支同常量合并与保留未使用的除零。单元测试覆盖全部 Mini C 预设与 60 个固定种子随机程序。现有实验 05 优化器仍保留可变变量实现，没有全局值编号、内存 SSA 或与寄存器分配联合的迭代合并。2026-11-26 核对 LLVM SCCP、Cornell CS 6120 讲义与 Briggs et al. 论文，未请求原书。

## 指令选择与代码生成（Instruction selection & code generation）

第二十二个实验 `/?lab=codegen` 把同一份 Mini C 程序的三地址代码翻译成 x86-64 汇编（Intel 语法、System V AMD64 调用约定），分四步回放：

1. **建树与树覆盖**：同一基本块内只用一次的临时值按“只取栈顶”接回使用处，后序展开顺序与原 IR 一致；再用最大吞进选择模式：比较与条件跳转融合为 `cmp` + 反条件跳转、`lea` 做三地址加法、三操作数 `imul`、`0 − x` 用 `neg`、超出 32 位的常量用 `movabs`。逐条模板展开作对照基线。
2. **语义检查**：每次加、减、乘之后与 r11 里的 2^53 − 1 比较（乘法先 `jo`），非常量除数先 `test` + `je`，越界与除零跳到 `__mc_trap`，报出与原 VM 相同的错误文本。
3. **带预着色约束的分配**：`cqo` / `idiv` 固定 rax、rdx，参数固定 rdi，`call` 写入全部 9 个 caller-saved 寄存器；物理寄存器作为已着色节点进入干涉图，跨调用活跃的值只能分到 rbx、r12–r15 或溢出。偏好着色让 mov 两端同寄存器后删去。可选 13 个通用寄存器或“紧张”的 rax / rcx / rdx / rbx。
4. **栈帧与执行**：序曲保存用到的 callee-saved 寄存器、布局 `[rbp − 偏移]` 栈槽并补齐 16 字节对齐；本项目的 x86-64 子集模拟器（BigInt 64 位寄存器、ZF / SF / OF / CF）在每次 call 时检查对齐、调用后把 caller-saved 寄存器与标志位置为未知、ret 时检查 callee-saved 与 rsp 已恢复。

可选输入为原始 IR 或实验 05 优化后的 IR；结果页对照 2 种输入 × 2 组寄存器 × 2 种选择方式的指令条数、检查条数、溢出、执行条数和行为。可展开完整的 `.s` 与运行时 C 代码，在 x86-64 Linux 上用 `gcc program.s runtime.c` 自行汇编；**这两份文件没有在本机用汇编器或真实 CPU 验证**，页面结果全部来自模拟器。7 个预设：原书 `a + b + 10`、比较与跳转融合、idiv 的固定寄存器、跨调用的值、32 位立即数放不下、64 位装得下但语言要报错、除零前的输出。单元测试覆盖全部相关预设与 60 个固定种子随机程序的 2 × 2 × 2 组合，独立重算分配冲突，并用手写的违规代码确认模拟器能发现寄存器被调用破坏、rsp 未对齐、callee-saved 未恢复与标志位失效。没有内存操作数、动态规划 / BURS 最优覆盖、区间拆分、函数调用与传参；执行最多 20000 条机器指令。2026-11-26 通过缓存脚本单页重读原书第 08 讲，并核对 Cornell CS 4120 指令选择讲义、x86-64 psABI 与 Intel 手册入口。

## 跨过程分析与内联（Interprocedural analysis & inlining）

第二十三个实验 `/?lab=interproc` 与实验 16 共用函数方言输入（前端检查全部复用），把函数接入三地址 IR 与已有优化链：

1. **降低**：用符号栈重读每个函数的栈式字节码，得到带 `call` / `return` 的三地址 IR。
2. **调用图与效果摘要**：Tarjan 强连通分量找递归，自底向上总结每个函数会不会输出、可能报错（未折叠的加减乘、除数不是非零常量的除法；`0 − x` 除外）、可能不终止（循环或递归环），并继承被调函数的效果；三样都没有才是纯函数。语言没有全局变量与引用参数，调用不会改调用者的局部变量。
3. **过程间常量传播**：在所有已执行调用点合并实参，函数内做条件常量传播并合并返回值，迭代到不动点。按结果替换常量、折叠、删除常量分支与不可达代码、删除没被调用的函数；**只有纯函数的调用才折叠成常量或删除**，有效果的调用即使结果确定也保留（结果没人用时只丢掉结果名）。改写后重新总结、传播，最多 4 轮——例如特化后的 `add(3, 4)` 变成 `return 7`，加法消失后才成为纯函数。
4. **内联**：按调用图自底向上展开不递归、不超过 16 条指令的函数；形参变复制，局部变量与标签加前缀，`return` 变成写结果加跳转。main 里没有 call 时交给实验 05 优化器（三项全开）与栈式 VM；仍有 call 时如实跳过。

实验 16 的函数字节码 VM 是基线；降低后、改写后、内联后的 IR 用带栈帧的解释器执行（同样 32 帧、2000 步上限），完全展开的 main 再走实验 05 优化器与栈式 VM，全部对照输出和错误。7 个预设覆盖原书第 15 讲的 `atLeastTen(3)`、两个调用点（传播得 ⊤、内联后仍可算出）、有效果的调用不能删、部分实参特化、改写后才变纯、结果没人用的除零、递归不能完全展开。单元测试覆盖两组预设与 60 个固定种子随机函数程序（含递归、循环、输出与报错），并核对生成器确实触发了报错、内联、调用删除与接入实验 05。没有上下文敏感分析、过程克隆、尾调用、逃逸分析或基于运行统计的内联。2026-11-26 把第 15 讲加入抓取脚本允许列表并单页读取，另核对 Cornell CS 6120 跨过程分析课与 LLVM IPSCCP 源码说明。
