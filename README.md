# 编译手记

基于宫文学《编译原理实战课》的中文交互笔记。参考同级 `transformer-animation` 的学习方式：**先预测，改输入，单步核对，再用自己的话复述**。本项目独立实现，不依赖兄弟项目运行。

## 本地运行

需要 Node.js 22.12+（或更新的受支持版本）和 npm。

```sh
npm ci
npm run dev
```

打开终端显示的地址（默认 `http://127.0.0.1:5173`）。所有编译与执行发生在浏览器中，无后端、账号或 API Key。仅在本仓库交付，没有创建云资源或发布网站。

```sh
npm run check       # 类型检查、算法与状态测试、生产构建
npm run test:e2e    # 桌面与手机尺寸的浏览器测试，需要本机 Chrome
npm run preview    # 本地预览生产构建
```

浏览器测试使用 Chrome channel；未安装 Chrome 时，可安装 Chrome，或在 `playwright.config.ts` 移除 `channel` 并安装 Playwright Chromium。

## 教学语言

```c
int result = 2 + 3 * 4;
print(result);

int x = 10;
{
  int x = 20; // 内层声明遮蔽外层
  print(x);
}
print(x);
```

支持 `int`、`bool`，变量声明和赋值，`+ - * /`、一元负号、括号、语句块、`print`、`//` 单行注释。语句需要半角分号。只有 ASCII 标识符；`int`、`bool`、`print`、`true`、`false` 是保留字。

整数使用 JavaScript 安全整数，除法向零取整，溢出和除零报告运行时错误。无隐式类型转换。初始化表达式先分析，新绑定随后引入；同层不能重复声明，内层允许遮蔽。源码限制 2000 字符，括号/一元运算/语句块嵌套限制 64 层。

支持 `if / else` 和 `while`，条件必须是 `bool`，主体必须用花括号。比较运算支持 `< <= > >= == !=`，算术优先于比较、比较优先于相等性。大小比较仅用于整数，相等性比较要求两侧类型相同。暂不支持 `break / continue`、逻辑短路、函数、字符串、浮点、闭包、对象与垃圾回收。IR 与字节码均为自定义教学格式，**不是 LLVM IR、JVM 或 CPython 的真实指令**，没有寄存器分配或机器码生成。

```c
int i = 1;
int sum = 0;
while (i < 4) {
  sum = sum + i;
  i = i + 1;
}
if (sum == 6) {
  print(sum);
} else {
  print(0);
}
```

第七个实验 `/?lab=cfg` 从原始 IR 划分基本块，再由虚拟机的真实执行快照生成按块回放的路径。图保留全部可能边，高亮本次实际经过的边；点击块可检查完整指令，前进/回退时变量与输出随快照更新。跳转使用生成的标签地址，不是写死的动画路线。

每次回放最多执行 2000 条字节码，避免错误循环阻塞界面。达到上限时明确显示暂停，**不代表已经证明程序不会终止**，暂停前的输出也不能用于判断完整行为等价。

## 算法与数据流

```text
source → tokenize → parse → analyze → generateIR → optimize → generateBytecode → execute
           tokens     AST     绑定/类型     TAC          TAC          栈式指令        快照
```

计算逻辑与 UI 分离，不使用 `eval` 或 `Function` 执行输入。每步状态来自真实扫描、构树、分析或执行。AST 回放展示最终树并高亮当时构建的节点，不伪装成增量生成的树。

直线代码沿用顺序传播与反向清理；**分支/循环已接入跨块优化**：先求解条件常量事实，再传播、折叠，最后依据可执行边删除不可达块，并在改写后的 CFG 上迭代活跃性，清理无用复制和标签。可能报错的未折叠算术仍然保留，输出与异常顺序不重排。三个开关分别控制表达式折叠、常量替换、分支/不可达与无用写入清理；分析本身不依赖开关，也不借用一次执行的结果。

第八个实验 `/?lab=dataflow` 展示原始 CFG 的分析：每次处理一个块，合并可执行前驱的 OUT，求出本块 IN / OUT，直到事实和边都不再变化。⊥ 是尚无信息，常量 c 是确定值，⊤ 表示不能确定唯一常量。循环可能让早期常量变成 ⊤；两条路径都赋 7 时仍可合并为 7。最后一步可选择任意块查看完整事实，也可查看原始结构图上的保守活跃变量集合。分析与执行快照清楚区分。

条件常量传播与活跃性均最多 200 轮；常量分析未收敛时保留原始 IR，不把未分析路径当成不可达。分析中间回放最多保留 240 次块处理，最终表始终展示完整分析结果，达到记录上限不会提前停止求解。实现为可变变量上的**稠密条件常量传播**，没有 SSA、φ、取值范围分析、循环展开或 LLVM 的稀疏实现。

页面实际运行原始版和优化版，比较当前程序的输出与错误；任一版本达到 VM 回放上限时，比较结果为无法判定。这个对照不等于一般性的语义等价证明，IR 指令数也不等于运行时间。

第九个实验 `/?lab=dominance` 从原始 CFG 的全部结构边求解支配集合，逐轮展示前驱交集与候选移除。完成后可查询 A 是否支配 B；若不支配，显示一条避开 A 的结构路径。直接支配树、自然循环的 header / latch / preheader / exit block、循环嵌套与支配边界都来自分析结果，不借用 VM 执行路径，也不按节点的绘图位置判断回边。

φ 面板按变量定义块计算**迭代支配边界的候选位置**，没有活跃性裁剪，所以可能多余；本页不生成版本名，不改写 IR 或执行候选 φ。继续到实验 13「静态单赋值」观察真正的 φ 插入与重命名。自然循环识别不等于枚举所有有向环或不可约区域。支配分析最多 200 轮，未收敛不发布后续结论；仅截断前 240 次块处理的回放，最终集合仍完整。结构可达与绕行路径不代表路径上的条件可同时成立。

## 正则与自动机

第十个实验 `/?lab=automata` 对应原书第 02 讲“用两种方式构造有限自动机”的第二种方式：只写词法规则，自动生成扫描器。输入格式借用 flex 的 `%%` 分隔：

```text
Int: int
Id: [a-zA-Z][a-zA-Z0-9]*
Num: [0-9]+
skip: [ \t\n]+
%%
int intA 42
```

`%%` 上方每行一条“名称: 正则”，越靠前优先级越高；名为 `skip` 的规则匹配后丢弃；`%%` 下方都是待扫描的输入。这个实验使用自己的输入，不经过 Mini C 编译；切换到其他实验时，原来的 Mini C 程序会保留。

回放分三段，每一步都来自 `src/compiler/automata.ts` 的真实计算：

1. **正则 → NFA**：按原书图 7–11 的拼接规则逐个子表达式构造。连接时把前一段的结束状态与后一段的开始状态合并；`* + ?` 和 `|` 用 ε 边。清单采用原书 `0 ε -> 2` 的写法。
2. **子集构造**：先求 ε-闭包，把全部边上的字符集切成互不相交的输入类，再逐个 DFA 状态求 move 与闭包。一个 DFA 状态同时含多条规则的接受状态时，取排在前面的规则；完全胜不出的规则和能匹配空串的规则会被标出。
3. **最长匹配扫描**：一直读到 DFA 无路可走，再回到最近的接受位置生成 Token，并显示退回的字符数。空词素不会成为 Token。

最后一步可以查看 DFA 图（键盘可选状态）、DFA 状态表、NFA 清单和“NFA 回溯对照”。回溯对照参照原书 `matchWithNFA` 的过程，按建边顺序深度优先做整串匹配，并列出每次尝试的状态和位置。它与 DFA 选出的规则一致，代价却可能大很多，例如 `(a|aa)*b` 在 12 个 a 上要尝试 4000 多次。

支持字符、`[ ]` 字符集与区间、`[^ ]`、`.`（除换行）、`\d \w \s`、`\n \t \r`、`| * + ?` 和括号；正则中的空格只用于排版。字母表限于 ASCII 可打印字符与 `\t \n \r`。本页不做 DFA 最小化，继续到实验 14 查看分割细化与扫描对照；不支持 `{m,n}`、锚点、捕获组和反向引用。限制为：最多 8 条规则，每条 80 字符，输入 300 字符；NFA 300 个状态，DFA 64 个状态。DFA 超限时停止构造，不发布扫描结果。扫描回放记录前 1500 步，Token 结果始终完整。回溯每个 Token 最多尝试 5000 次，只显示前 240 次。

单元测试用 JS `RegExp` 加暴力最长匹配作为独立对照，检查全部预设和额外用例的 Token 与报错位置。原书未展开子集构造，只推荐龙书第 2 版 3.7.1 节（纸质书，未在线核对）。2026-11-18 另核对 [Russ Cox 关于 Thompson NFA、回溯与 DFA 的文章](https://swtch.com/~rsc/regexp/regexp1.html)。

## 文法与预测分析

第十一个实验 `/?lab=grammar` 对应原书第 03 讲“两个基本功和两种算法思路”。实验 02 演示了手写的递归下降，这里接着回答：一个规则有几种写法时，解析器怎样只看下一个 Token 就选对。输入同样用 `%%` 分隔：

```text
exp -> mul add'
add' -> + mul add' | ε
mul -> pri mul'
mul' -> * pri mul' | ε
pri -> Num | ( exp )
%%
2 + 3 * 4
```

`%%` 上方每行一条产生式，候选用 `|` 分开，空串写 `ε`，以 `|` 开头的行接着上一行；第一条的左边是开始符号。出现在左边的名字是非终结符，其余都是终结符。输入可省略空格：与终结符同名的单词和符号直接对应，文法里有 `Num` / `Id` 时，数字和其余单词分别记作它们。

回放分四段，全部来自 `src/compiler/grammar.ts` 的真实计算：

1. **FIRST**：一轮轮扫描全部产生式，把能借到的 Token 加进去，直到某一轮没有变化（不动点）；每一步说明这个 Token 是从哪里借来的。
2. **FOLLOW**：开始符号先放 `$`，再按“后面是什么”和“在末尾就继承左边”两条规则迭代。
3. **分析表**：逐条产生式填表，因 FOLLOW 填入的格子标 F；格子里有两条时报告 FIRST/FIRST 或 FIRST/FOLLOW 冲突，并且不做解析。
4. **用表解析**：显示栈、输入光标、本次查到的格子，解析树随步骤长出来；出错时说明此处能接受哪些 Token。

能识别直接与间接左递归，用“解析 add() → 解析 add() → …”演示递归下降为何停不下来；直接左递归可一键改写成 `A -> β A'`、`A' -> α A' | ε` 后重新分析。移进 / 规约见实验 12；本实验不提取左公因子、不做错误恢复。限制为：16 个非终结符、40 个候选、每个候选 10 个符号、输入 60 个 Token、解析回放 600 步。

单元测试用龙书经典表达式文法的 FIRST / FOLLOW 作为参照，另用“列举文法能生成的全部短串”作为独立对照，检查表驱动解析的接受与拒绝，并确认左递归改写前后接受同一组短串。

## 移进与规约

第十二个实验 `/?lab=lr` 对应第 03 讲后半的 LR 算法：不从树根往下猜，而是把 Token 移进工作区，凑齐一条产生式的右边再规约成左边的名字。文法写法与实验 11 相同，FIRST / FOLLOW 也复用实验 11 的计算。

1. **项目集**：自动加上 `S′ → 开始符号`，从“带点的产生式”出发求闭包，按点后面的符号前进，得到全部 LR(0) 状态；每个项目注明来自哪个状态或因哪个名字被闭包加入。
2. **ACTION / GOTO**：点后面是 Token 就移进；点在末尾且下一个 Token 属于 FOLLOW(左边) 就规约（SLR(1)）；同一格有两个动作时报告移进/规约或规约/规约冲突，不做解析。
3. **移进 / 规约**：工作区按栈顺序显示状态号和已经拼好的小树，规约时几块合成一块；移进时若已有完整项目却不规约，会说明下一个 Token 不在 FOLLOW 里。接受后列出最右推导，即规约顺序倒过来读。

原书示例的左递归文法 `add -> add + mul | mul` 不用改写即可解析，乘法优先、加法左结合；实验 11 中“开头相同”的 LL(1) 冲突文法在这里也没有冲突。原书示例称 LR(1)，本实验采用更简单的 SLR(1)：例如 `S -> L = R | R`、`L -> * R | Id`、`R -> L` 在 SLR(1) 下有冲突，页面会如实报告。不实现完整 LR(1) / LALR、错误恢复和按优先级消解冲突。最多 80 个状态，解析回放 600 步。

单元测试核对经典表达式文法的 12 个 LR(0) 状态，对解析树求值验证优先级与结合性，检查最右推导每一步都展开最右边的非终结符，并用“列举文法能生成的短串”作为独立对照。

2026-11-17 核对 [Cornell 支配关系与 SSA 讲义](https://courses.cs.cornell.edu/courses/cs4120/2026sp/notes/reachdef/index.html)与 [LLVM 循环术语](https://llvm.org/docs/LoopTerminology.html)。新增实验沿用现有笔记、JSON 导入/导出和分享；旧版笔记兼容。本次扩展没有请求电子书站点。

## 静态单赋值（SSA）

第十三个实验 `/?lab=ssa` 接着实验 09 的 φ 候选继续，输入仍是同一份可编辑 Mini C 程序。构造使用原始结构 CFG，不按某次执行或常量条件删除结构边：

1. 从变量定义块沿支配边界迭代，仅在变量入口活跃时插入 φ；候选表列出保留与裁掉的位置。
2. 沿支配树维护版本栈，先读操作数，再给写入分配版本；为后继 φ 填上当前前驱对应的版本。离开子树时弹栈，版本计数器继续递增。
3. 校验定义唯一、普通使用受定义支配、φ 输入与可达前驱一一对应，以及输入定义支配对应前驱的末尾。
4. 用独立 SSA 解释器执行，块首 φ 根据实际前驱同时读写；和原始栈式 VM 对照输出与错误。循环动态重复执行同一处静态定义，不按迭代创建新名字。

构造与执行各保留前 240 步中间记录，完整 SSA 与最终执行结果不受记录截断影响。SSA 解释器最多执行 2000 次操作；其计步单位与 VM 字节码不同，任一达到上限就显示“暂不能判定行为一致”。核对针对当前输入，不是通用等价证明。

本实验范围是标量局部变量的活跃性裁剪 SSA，没有内存 SSA、指针、函数或基于 SSA 的优化，SSA 消除见实验 15；现有优化器继续使用可变变量 IR，原始 IR 不被改写。2026-11-21 核对 [Cornell 的 SSA 构造与活跃性讲义](https://courses.cs.cornell.edu/courses/cs4120/2026sp/notes/reachdef/index.html)和 [LLVM φ 输入语义](https://llvm.org/docs/LangRef.html#phi-instruction)，未重新请求原书。新增实验沿用本地笔记、旧 JSON 导入和不含笔记的分享 URL。

## DFA 最小化

第十四个实验 `/?lab=minimize` 接着实验 10，用相同的“名称: 正则 / %% / 输入”格式，提供 7 个预设。按获胜规则编号做 Moore 式分割细化，逐步展示后继分组签名导致的拆分；完整机中补入可达的隐式 Dead 状态，达到稳定分组后，每个组成为一个新状态。

可以选择任意两个原始可达状态，广度优先搜索它们的状态积，找出最短区分后缀；空串 ε 可以区分当前就输出不同规则的状态。穷尽状态对仍没有反例时，它们才等价。词法扫描器必须保留具体的获胜规则，不能把所有接受状态合在一起。

最小化结果另用独立状态积搜索，在整个支持字母表上校验获胜规则；随后调用同一最长匹配扫描算法，对照 Token 的规则、文字、起止位置、skip 和首次失败位置。原始与最小化状态编号及试读细节可能不同。`ab|cb` 的原始 5 个状态缩为 3 个扫描器状态；包含可达 Dead 的完整机为 6 → 4。导出时继续省略 Dead 类与失败边，空语言保留一个拒绝入口。状态不一定减少，也不代表每个字符会少执行一步。

规则与输入沿用实验 10 的大小限制；DFA 子集构造到 64 个状态仍未完成时，不运行最小化、校验或扫描。实现不是 Hopcroft，也没有 NFA 最小化、Unicode 或运行时网络请求。2026-11-21 核对 [Cornell DFA 最小化与词法动作讲义](https://www.cs.cornell.edu/courses/cs4120/2026sp/notes/leximpl/)，未重新请求原书。单元测试采用独立的表填充算法核对分组和最小性，并枚举短输入与直接正则最长匹配对照。旧笔记、导入导出与不含笔记的分享 URL 均继续兼容。

## SSA 消除（Out of SSA）

第十五个实验 `/?lab=outssa` 接着实验 13，把 φ 还原为边上的普通复制。仍输入同一份 Mini C，先构造并校验 SSA，再按前驱收集一组并行复制：前驱只有一条后继边时放在前驱末尾；否则，后继只有一个前驱时放在后继入口；两端都不满足时拆分关键边，新增 E 编号的边块。转换保留原始结构边，不借用本次 VM 经过的路径。

并行复制先安排不再被读取旧值的目标；形成环时用新的临时变量保存旧值，自身复制省略。保留版本名的 Mini C SSA 不一定直接形成复制环，因此页面另有可编辑的小实验，对照同时赋值、直接按列表执行和正确调度的结果。它使用相同调度器，但独立于主程序，也不写入主程序分享链接。

转换结果重建普通赋值、运算、输出、标签和显式跳转，交给原有 `generateBytecode` 与栈式 `execute` 执行，不使用 SSA 解释器冒充消除后的 VM。页面比较原始 VM、SSA 解释器和消除后 VM 的输出与错误，回放真实 PC、操作数栈和输出。任一执行达到上限就显示无法判定；不同表示的指令数量和计步方式不能直接当成运行时间。

这是保留独立版本位置的基础消除，没有复制合并、寄存器分配或 SSA 上的优化。程序限制仍为 2000 字符；转换 IR 最多 10000 条，VM 最多 2000 条字节码，构造与 VM 各记录前 240 步，最后一步仍保留完整最终状态。仅在进入本实验时计算消除结果，其他实验继续沿用现有路径。

2026-11-21 核对 [Cornell Out of SSA](https://www.cs.cornell.edu/courses/cs6120/2025sp/lesson/6/)与 [CMU SSA Deconstruction](https://www.cs.cmu.edu/~15411/rec/02.pdf)，没有重新请求原书。测试包括随机复制排列和扇出、复制环、关键边、单前驱入口、原 VM 上的循环交换、输出/异常顺序、预算和旧笔记兼容。

## 函数与调用栈（Functions & call stack）

第十六个实验 `/?lab=functions` 使用独立函数方言，复用现有扫描器和安全整数运算，先登记全部函数签名，再检查作用域、实参类型与完整返回路径，直接生成带 `CALL` / `RETURN` 的函数字节码。已有 Mini C、CFG、SSA 和优化路径保持原来的范围；函数调用未经过旧优化器。

```c
int fact(int n) {
  if (n <= 1) { return 1; }
  return n * fact(n - 1);
}
print(fact(4));
```

按值传递 int / bool，实参从左到右各求值一次。每次调用拥有独立局部变量表、操作数栈和返回位置。页面可以检查暂停的调用者，观察递归保留的参数与待完成运算，回放实际调用/返回记录和输出。顶层语句构成独立入口帧，变量不是全局变量；调用名使用独立函数表。函数须在静态结构上覆盖所有返回路径，while 不算保证返回。

10 个预设包含阶乘、相互递归、形参副本、嵌套求值、局部循环、输出后的除零、缺少返回、错误作用域与深度上限。最多 2000 字符、24 个函数、8 个形参、32 个活动帧（含入口）及 2000 条执行指令；中间状态保留前 400 个，最终现场、统计与输出完整保留。运行时错误停止后续执行并保留调用链，上限只表示暂停。没有闭包、void、引用参数、异常展开、尾调用优化或真实 ABI。

2026-11-21 核对 [Cornell Calling Conventions](https://www.cs.cornell.edu/courses/cs3410/2026sp/notes/asm-call.html) 与 [《Crafting Interpreters》作者的 Calls and Functions](https://github.com/munificent/craftinginterpreters/blob/master/book/calls-and-functions.md)，未重新请求原书。左到右求值与每帧独立操作数栈是本实验约定，不是 C 或真实机器 ABI 的规范。
